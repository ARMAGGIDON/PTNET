# PT.NET — лабораторна робота №8

Консольний каталог дисків (варіант 8) з постійним зберіганням даних у **SQL Server LocalDB** через **ADO.NET**.

Цей файл описує реалізацію з погляду розробника. Формулювання навчального завдання зберігається окремо в [task.md](task.md).

## Вимоги та запуск

- Windows 10/11 і термінал із підтримкою ANSI/VT та альтернативного буфера (наприклад, Windows Terminal).
- .NET SDK 10, установлений SQL Server LocalDB з екземпляром `(localdb)\MSSQLLocalDB`.
- Доступ до LocalDB від поточного користувача Windows.

З кореневої теки `PTNET`:

```powershell
dotnet restore
dotnet run --project lab08
```

У терміналі потрібно щонайменше **100 стовпців × 30 рядків**. TUI використовує фіксовані **96 × 27** комірок. За недостатнього розміру відображається повідомлення, а навігація призупиняється (можна натиснути `Esc`).

## Доступ до даних

Підключення навмисно задане без додаткових файлів конфігурації чи змінних середовища:

- SQL Server: `(localdb)\MSSQLLocalDB`
- База: `PTNET_Lab08`
- Таблиця: `dbo.Discs`
- Авторизація: інтегрована Windows

`DiscRepository.Initialize()` створює базу та таблицю, якщо їх немає. **П'ять демонстраційних записів вставляються лише при першому створенні таблиці**: видалені користувачем записи не відновлюються при повторному запуску.

Поля: `Code INT PRIMARY KEY`, `Topic NVARCHAR(100)`, `Title NVARCHAR(150)`, `ReleaseYear INT`, `Price DECIMAL(10,2)`. Перевірки типів/меж виконуються як у формі, так і на рівні SQL-обмежень.

Читання здійснює `SqlDataReader`, зміни — параметризовані `SqlCommand` з `ExecuteNonQuery()`. Кожна операція відкриває і звільняє власне `SqlConnection`; таблиця не симулюється звичайним списком у пам'яті.

Приклад перевірки розташування файлів БД у SQL-консолі:

```sql
SELECT name, type_desc, physical_name
FROM sys.master_files
WHERE database_id = DB_ID(N'PTNET_Lab08');
```

## Рендеринг і стан форм

`CatalogApp` зберігає стан форми (`Catalog`, `Editor`, `ConfirmDelete`), поточну позицію та введені дані. Обробники клавіш не містять SQL-текстів — це відповідальність `DiscRepository`.

`TerminalCanvas` використовує **альтернативний буфер термінала** (ANSI `?1049h`/`?1049l`), щоб не пошкоджувати scrollback PowerShell. Екран має стабільні координати. `BeginFrame()` формує наступний кадр в пам'яті, `Render()` порівнює його з попереднім і переписує тільки змінені рядки. Під час переходу між формами або після зміни розміру вікна попередній кадр інвалідується.

Активний рядок каталогу виділений білим текстом на темно-синьому фоні з маркером `>`; горизонтальні псевдографічні розділювачі не використовуються.

## Обмеження

- TUI орієнтований на **Windows Terminal**; альтернативний буфер підтримується не всіма середовищами запуску IDE.
- Поточна реалізація читає весь каталог і виконує пагінацію в пам'яті; для великої кількості записів доцільна SQL-пагінація.
- SQL-операції синхронні: при затримках LocalDB інтерфейс може короткочасно не реагувати.
- Дані зберігаються у файлах `.mdf` та `.ldf`, якими керує SQL Server LocalDB, а не в теці збірки `bin`.

## Основні точки розширення

Нові поля спочатку додають до `Disc`, схеми таблиці та SQL-запитів `DiscRepository`, потім — до валідації та форми `CatalogApp`. Зміни екранних стилів виконуються в `CatalogApp`, а алгоритм точкового перемальовування ізольований у `TerminalCanvas`.
